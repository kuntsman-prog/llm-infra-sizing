# Сайзинг LLM-инфраструктуры и референсная архитектура AI-платформы

[English](README.md) | **Русский**

Два инструмента для первого этапа любой AI-платформы, когда нужно ответить, сколько GPU нужно, какие и во что это обойдётся:

1. **Калькулятор сайзинга.** По модели, квантизации, профилю нагрузки и целевой задержке подбирает конфигурацию на разных GPU: tensor parallel, батч, число реплик и серверов. Сравнивает стоимость своего оборудования, аренды GPU и API на горизонте трёх лет.
2. **Референсная архитектура AI-платформы с нуля:** [AI_PLATFORM_ARCHITECTURE.ru.md](AI_PLATFORM_ARCHITECTURE.ru.md). Что строить и что пока не строить, стратегия моделей, LLM-платформа, знания и RAG, агенты и их права, безопасность и DR, облако или своё оборудование, этапы, порядок найма, риски.

## Веб-версия

`docs/index.html` это тот же калькулятор в виде одной страницы, которая работает в браузере: выберите готовый сценарий или задайте свою нагрузку, и таблица GPU, задержка и стоимость на несколько лет пересчитываются при каждом изменении. Цены GPU и инженерные допущения (PUE, обслуживание, ставка дисконтирования, эффективность движка, целевая загрузка) можно править прямо на странице; таблицу можно сократить до колонок для бизнеса. Сервер не нужен.

Публикация на GitHub Pages: Settings → Pages → Build and deployment → Deploy from a branch → `main`, папка `/docs`. Руководство пользователя для бизнес-заказчика с пояснением каждого поля и примерами: [GUIDE.ru.md](GUIDE.ru.md). Страница будет доступна по адресу `https://kuntsman-prog.github.io/llm-infra-sizing/`. На трёх готовых сценариях она даёт те же результаты, что и расчёт на Python.

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m sizing.cli ask                                         # ввод параметров по вопросам
python -m sizing.cli calc --model qwen2.5-14b --quant fp8 --users 500 --prompt 1500 --gpu l40s --gpu h100-sxm
python -m sizing.cli calc --help                                 # все параметры командной строки
python -m sizing.cli scenario config/scenarios/assistant.yaml   # готовый сценарий: корпоративный ассистент с RAG
python -m sizing.cli scenario config/scenarios/agents.yaml      # агентная платформа на модели 70B
python -m sizing.cli scenario config/scenarios/documents.yaml   # пакетная проверка документов на MoE
python -m sizing.cli kv llama-3.1-70b --context 8000 --sequences 32
python -m sizing.cli models
python -m sizing.cli gpus
python -m pytest
```

Режим `ask` задаёт вопросы по очереди: значение по умолчанию показано в скобках, Enter оставляет его, некорректный ввод переспрашивается. В конце параметры можно сохранить как сценарий и пересчитывать его командой `scenario`. Сценарий также можно описать в YAML вручную: модель, квантизация, число пользователей, запросы в день, вызовы модели на запрос, доля трафика в пиковый час, длина промпта и ответа, целевые TTFT и время на токен, нужен ли резерв.

## Методика

**Память.** Веса: параметры × байт на параметр (FP16 2, FP8 1, INT4 0,5). KV-кэш на токен: 2 × слои × KV-головы × размер головы × байт. Grouped-query attention сокращает KV-кэш в разы: у Llama 3.1 70B это 320 КБ на токен вместо 2,5 МБ при полном числе голов. Движку инференса отдаётся 90% памяти GPU, плюс резерв на каждый GPU.

**Генерация (decode)** ограничена пропускной способностью памяти: на каждом шаге читаются веса и KV-кэш всех запросов батча, а выдаётся по токену на запрос. Поэтому батчинг почти бесплатно увеличивает пропускную способность, пока чтение KV-кэша не сравняется с чтением весов. Для MoE учитывается, что с ростом батча задействуется больше экспертов.

**Обработка промпта (prefill)** ограничена вычислениями: около 2 × активные параметры FLOP на токен.

**Подбор.** Для TP = 1, 2, 4, 8: веса и KV-кэш должны поместиться; батч максимальный при целевом времени на токен; пропускная способность реплики учитывает паузы на prefill; число реплик рассчитывается из пикового потока и целевой загрузки 70%, плюс резервная. Через PCIe обмен между GPU дороже, чем через NVLink. Выбирается вариант с наименьшим числом GPU.

**Стоимость.** Своё оборудование: GPU и доля сервера, электроэнергия с учётом PUE, обслуживание 10% в год. Облако: аренда GPU круглосуточно или в рабочие часы. API: цена за входные и выходные токены. Зарплаты команды не учитываются.

## Ограничения

- Это оценка по roofline-модели с точностью ±30–50%. Перед закупкой нужен нагрузочный тест на vLLM с реальными промптами.
- Коэффициенты эффективности (60% пропускной способности памяти, 40% вычислительной мощности) типичны для современных движков, но зависят от версии, модели и настроек.
- Не учтены кэш префиксов, спекулятивное декодирование, разнесение prefill и decode на разные GPU: все они улучшают результат, поэтому расчёт консервативный.
- Параметры моделей взяты из config.json; для своей модели сверьте значения.
- RTX 4090 показана для сравнения: лицензия драйвера GeForce не разрешает размещение в ЦОД, поэтому карта не участвует в рекомендациях.

## Структура

```
sizing/
  catalog.py   модели, GPU, сценарии
  memory.py    память под веса и KV-кэш
  perf.py      roofline-оценка генерации и prefill, MoE
  plan.py      подбор TP, батча, реплик
  cost.py      своё оборудование, облако, API
  cli.py       командная строка: ask, calc, scenario, kv
  interactive.py  ввод параметров по вопросам
config/models.yaml      параметры моделей
config/gpus.yaml        характеристики GPU и экономика
config/scenarios/       сценарии нагрузки
docs/index.html         веб-версия калькулятора (GitHub Pages)
GUIDE.ru.md             руководство пользователя калькулятора
AI_PLATFORM_ARCHITECTURE.ru.md   референсная архитектура AI-платформы (английская версия без .ru)
tests/                  автотесты; test_control.py: контрольный пример, посчитанный вручную по шагам; test_web_parity.py: веб-версия совпадает с Python (нужен Node.js, без него тест пропускается)
```
